# AI Agent MVP 后续迭代路线图

本目录汇总 `ai-agent-mvp` 项目距离"生产可用 AI Agent"还缺哪些模块，以及推进顺序。

## 阅读顺序

1. `module-inventory.md` — 现状清单：已有什么、缺什么、每项归入哪个优先级
2. `P0-critical.md` — 阻塞级：不做会影响 Agent 基本正确性
3. `P1-important.md` — 生产就绪级：影响可用性、生态接入与可运维
4. `P2-enhancement.md` — 能力扩展级：让 Agent 更聪明、更可控
5. `P3-nice-to-have.md` — 工程化加分项：交付效率与体验

## 优先级定义

| 级别 | 判定标准 | 典型代表 |
|------|----------|----------|
| **P0** | 决定 Agent 是否能"正确工作"；缺失会导致多轮失败、非确定性输出或不可调试 | 会话记忆、原生 function-calling、重试/超时、单元测试 |
| **P1** | 决定是否能"生产上线"；影响运维、生态与真实业务 | MCP、真实 search、可观测性、持久化、鉴权 |
| **P2** | 决定 Agent 的"智能上限"与"治理能力" | RAG、Prompt 模板、成本追踪、子 Agent、评测 |
| **P3** | 工程化加分，与业务功能无强耦合 | Docker/CI、OpenAPI、流控、安全护栏 |

## 如何使用本路线图

- **单人推进**：按 P0 → P1 → P2 → P3 顺序执行；同一级内按文档中"建议顺序"推进
- **多人并行**：以任务粒度立卡；标注依赖关系（见每个 P 文档末尾的"依赖图"）
- **每次改动**：走 SDD 流程（doc.md → tasks.md → 实施 → summary.md），单个任务原则上不跨越多个优先级
- **评估收敛**：每完成一个优先级，建议跑一次端到端评测（P2 有专门任务定义 golden set）

## 约束

- 所有任务默认不允许引入付费或强供应商锁定的 SaaS 依赖，除非文档中显式说明
- 保持现有技术栈（Fastify v4 / TS 6 / ESM / NodeNext）；新增运行时依赖需说明理由
- 不为已删除代码留兼容层；对外接口若变更需在同一 PR 中更新 `test.ts` 与 `public/index.html`
